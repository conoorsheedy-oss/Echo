# Changelog

## 0.2.0 – unreleased

- **Ask panel in Interview mode answers interviewer questions like the answer card.** Typing "Design a URL shortener" or "Tell me about yourself" into Ask now gets the full interview answer (same prompt, rules, format, thinking level, brief and story bank as a spoken question). Questions for the assistant ("what should I say?", "what did they mean?", "summarise") still get the chat reply.

- **Settings > Answers: Detailed (default) or Strict.** Detailed (adapted from a friend's fork) gives longer, richer answers (about 200-300 spoken words for big behavioural questions and project walkthroughs) and drops the strict fact rules: no TRUTH FIRST, no [placeholder] fallback, no "never add a setback" rule. Check names, numbers and stories before you say them. Strict is the previous behaviour: short answers, only facts from your files, [placeholders] for anything missing.

- **Better grounding (ideas from a friend's fork).** Search counts generic interview words ("tell", "time", "project", "experience"...) at a fraction, scores very short chunks as if longer, and returns at most 2 snippets per file. Plans and cheat sheets aren't treated as proof: "what to say", "suggested tests", "future improvements" are suggestions, and prototyped / approved / shipped / measured stay separate. Technical details the files don't cover are explained as an example ("if I were building it..."), never as the user's own work.

- **Fix: invented project details in "tell me about yourself".** Keyword search was returning a bare heading ("Project deep-dive 1: ovgraph (lead with this)") instead of the profile, and the model described the project from its name. Short headings now always stay with the paragraph under them; intro questions ("tell me about yourself", "walk me through your CV") also search with profile words and favour profile / about / CV files; and the prompt forbids describing anything from its name alone.

- **Your intro (brief).** A new optional field for your real "tell me about yourself" answer. Echo uses it every time (same facts, same order, your words), only shortening it or pointing the last line at the role; the first line opens with it. No more different intro each time.
- **No upgraded facts:** year of study, title, seniority ("final year"), how long ago, how big a speed-up: only exactly as written. "I'm excited", "excited about" and "which is why I'm…" closers are banned; Ask panel lines stay under ~15 words.

- **Fixes from the Microsoft mock.**
  - **Same story every time.** The first story told for a theme (a disagreement, a failure, leading...) becomes your go-to for it, kept across interviews and rebuilds: next time it's picked first and told the same way (same facts, same order, same part for each person). Within one interview it still gives way once told. The Knowledge drawer shows "go-to for disagreements" next to it.
  - **Nobody looks bad:** a disagreement is two reasonable views and how it was settled, never someone careless or hiding something.
  - **Scaling follow-ups finished** (a stream, memory limits, several machines): the concrete technique and how the parts combine, never just "we'd need something distributed". They're detected as follow-ups ("how would you make it work across many machines?") and think at `medium`. Every stated complexity is checked against its operations.
  - **"Why this company?"** names a specific team, product or engineering choice from the brief or ad, or a [placeholder] for one, never the line every candidate says.
  - "First things first" joins the banned phrases.

- **Story builder.** When Echo builds your story bank it also drafts story *ideas* from your project details (a failover feature -> something broke; a fixed bug -> a mistake you caught), one per theme your real stories don't cover. Each is tied to an exact line from your files and adds no numbers. In Interview mode, a behavioural question with no matching story shows the idea on the answer card, dashed and marked "not confirmed", with **It happened** / **Something like it** (fix it first) / **Didn't happen**. The answer itself never uses an unconfirmed idea. Confirmed ones are saved to `my-stories.md` and become real stories; rejected ones never come back. The same ideas are listed in the Knowledge drawer to go through before an interview.

- **Engage before coding.** A new coding or design problem now opens with one short clarifying question for you to ask (input size, an edge case, the time complexity they want, or for design the scale), about something the problem doesn't already say; the approach, walk-through and code follow for when they answer. The instant first line is that question too.
- **Commented code:** short comments on the key lines (about 3-6), not on every line.
- **Compact but specific:** fewer words, more concrete detail.

- **Fixes from the second mock interview.**
  - **No code read aloud.** Spoken lines never contain identifiers, underscores, brackets or quotes; code is named in plain words ("a set of the IDs I've seen") and only appears inside the code block.
  - **Failure-case follow-ups** (a crash, a retry, two requests at once) get a proper answer: what's written before the risky step, how it recovers, what stops duplicates. They're detected as follow-ups after a design or coding answer and think at `medium`.
  - **"Why this company?"** leads with your own real connection to it. A CV line that names the company (e.g. you integrated Stripe) is added to the background when the brief names that company.
  - **Stories:** about 30 seconds, the technical choice in the first line, and your own part made explicit ("I did X; my lead did Y"). Numbers are never mixed between places.
  - **Add a real story** (Knowledge drawer): write a true story in a few lines; it's saved to `my-stories.md` in your knowledge folder and goes into the story bank, so you tell the same story every time.

- **Fixes from a mock-interview review.**
  - **Your terms are heard right.** Names and specs from your knowledge files and brief (e.g. `NIST SP 800-22`, `PayDai`, `FastAPI`) go to Deepgram Nova-3 as keyterms and to Groq Whisper as a short prompt, so they're transcribed correctly. Only the terms are sent, never sentences. A Whisper transcript of the prompt itself (over silence) is dropped. Answers are also told to use the right term when the transcript garbles one ("SP 822" -> "SP 800-22").
  - **Easier to say, not read.** Script lines are under ~15 words, one idea each. Technical walk-throughs are 3-4 steps that each start with a **bold cue** and make sense alone (no "first... then three"). Trade-offs are one contrast you can say in one breath. Formulas are said in words once and checked, with every increment / decrement.
  - **"Any questions for me?"** always gets two real questions to ask (tailored to the brief), never "no questions"; the first line gives the first one.
  - **No bent stories.** If none of the picked stories has the theme the question asks for (a disagreement, a failure, leading people...), Echo is told not to turn one into that kind of story and to use [placeholders] instead. The answer card shows which real story an answer told: `Your story: Ledgerly (cv.md)`.

- **Ask panel answers like the answer card.** Typing an interview question into Ask ("tell me about something you're proud of") now gets a spoken answer: no "Here's an answer you can give" intro, no quotes around it, no closing moral, about 45 seconds at most, facts only from your files (the Ask panel now has the same TRUTH FIRST rule), and in Interview mode the story bank. Every prompt's TRUTH FIRST rule now also forbids adding a setback, team size, duration, number or "what it led to" to make a story sound real.

- **CV story bank.** Echo reads your knowledge files once (and again only when they change) and pulls out your real stories. Every quote is checked word for word against the files and any number that isn't in them is dropped, so invented details don't get in. In Interview mode a new behavioural question gets the 2 best-fitting stories (theme, the question's words, the role from the brief), preferring ones you haven't told yet this session; the first line opens with the top one. On by default; switch it off in the Knowledge drawer (then your files are never sent whole). The drawer lists the stories found.

- **Interview brief.** A new dock drawer where you tell Echo what you have before an interview, all optional: company and role, the job ad, the interview type (Behavioural / Coding / System design / Recruiter-HR screen / Mixed / Auto) and notes. Interview mode only; an empty brief changes nothing.
  - The ad steers which of your real projects Echo talks about; "have you used X?" gets an honest answer when X isn't in your CV; company facts only come from what you wrote (otherwise a `[placeholder]`). Notes are your own facts (`[From brief]`).
  - A long job ad is condensed once on save (Flash-Lite, ad text only); until then Echo uses the start of it.
  - Coding and system design rounds think at `medium` on technical follow-ups (Quality = Auto).
  - Behavioural questions get one extra CV snippet that best matches the role.
  - Saved locally in `interview-brief.json`; Diagnostics > Thread shows what's in use.
  - The Ask panel gets the brief too (Interview mode).
- **Follow-up detection:** after code, short questions about complexity, edge cases, trade-offs or tests ("what is the complexity of that?") now count as technical follow-ups, not new general questions.

- **Simpler, more natural voice prompt.** The "sound human" rules are now a short list of positive rules (copy the user's own "You" lines first, one idea at a time, no wrap-up, vary openers) with four question-shaped tone examples of different lengths, instead of a long list of don'ts with BEFORE/AFTER pairs that the model tended to imitate ("Honestly," on every answer). Facts still come only from the transcript or CV (TRUTH FIRST).
  - Gemini 3 models now run at their default temperature (Google's advice: lower values can cause looping); custom temperatures only apply to older models.
  - The first line no longer cuts at "e.g." / "i.e." / "vs." etc.
  - Whisper keeps a real "Thank you." (end of an interview) and only drops stock phrases when it doubts there was speech.
  - The recorded request-body snapshots (`test/fixtures/prompt-snapshots-2a.json`) were refreshed for the new system prompt; user messages are unchanged.

- **Interview state in answers (Phase 2b).** Interview-mode answers now see what Echo knows about the interview so far, as a compact **INTERVIEW STATE** block (≤ 1500 chars) after the background and before the question. Every line says where it came from: `[Interviewer]`, `[You said]` (your own lines verbatim, and details you actually said: `[You said — confirmed: "hash map"]`), `[From CV: file]`, and `[Echo suggested — not confirmed]` for Echo's earlier answer and code. It holds the current thread (original question, follow-ups, constraints, interviewer facts), what you said in it, Echo's last suggestion (code only for technical threads, elided if long), and one line per other thread; when a question could belong to two threads it lists both readings, and it says when a question refers back to an older thread. When it's too long, whole lines are dropped in a fixed priority order (link uncertainty, the question, what you said, constraints, Echo's suggestion, other threads).
  - **One direction for both answers**: a deterministic `Direction:` line in LATEST, e.g. "follow-up on #1 (two sum) — answer in terms of the approach the candidate described: two pointers [You said]" or "stay with the same story (Kobo [You said]; [From CV: cv.md])". It only uses what you said or your CV, never Echo's unconfirmed suggestion; with no CV it asks for [placeholders].
  - The instant first line gets the same block (trimmed to 900 chars, a subset of the full one) and the same Direction line, computed once per request, so the first sentence and the full answer agree.
  - The interview system prompt explains the labels ("follow the candidate's version, never treat [Echo suggested] as theirs"); it's still fixed per mode and style, and the transcript still comes first, so prompt caching works as before. The first question of a session adds no block.
  - Meeting, Presentation and General requests are byte-identical to before (checked against recorded request bodies). If the session state ever fails, the answer goes out without the block.
  - Diagnostics > Thread adds `State block: N chars (thread #k, link 0.82)`.

- **Early start on Deepgram interim text.** When Deepgram's end-of-speech signal (`speech_final`) doesn't fire -- seen with an AI interviewer's voice played through system audio -- the answer used to wait for the ~1 s `UtteranceEnd` fallback (about 1.5 s from speech end to request). Now, in Deepgram mode, once the interviewer's in-progress line reads like a complete question that needs an answer and no new words have arrived for 350 ms, the automatic answer starts from that text.
  - When the final line arrives with the same words (punctuation, "um", a trailing "okay?" don't count), the answer already in flight is kept: no second request. If they kept talking or the words changed, the corrected question is asked instead and replaces the early answer -- unless that answer has been on screen for 1.5 s, in which case it finishes and the corrected one waits behind **New answer ready**.
  - Only for the other side's speech and automatic answers; never in Privacy Mode or with Groq Whisper. Interim text is still never added to the transcript Gemini sees.
  - An early answer is attached to its question's thread once the line lands (interview session), so follow-ups still find its code and CV snippets.
  - Diagnostics > **Last answer timing** now starts with what released the answer: `trigger: speech_final`, `utterance_end`, `early_interim` (with `kept` / `restarted`), `groq_vad` or `other`, plus how long after the last audio that signal came.

- **Faster first word.**
  - Deepgram now calls the end of speech after a 200 ms pause (was 300 ms), so automatic answers start ~0.1 s sooner. `utterance_end_ms=1000` stays as the fallback. Override with `DEEPGRAM_ENDPOINTING_MS` (100-1000).
  - The instant first line now uses the newest stable Gemini **Flash-Lite** your key can use, found once per run from Gemini's model list (no `-preview` / `-exp` / dated ids). The lookup never delays a request: until it finishes, or if there's no stable Flash-Lite, the first line uses `GEMINI_MODEL` as before. A first-line model that 404s is dropped for the run; one that refuses `minimal` thinking is retried at `low`, then without thinking. Set `GEMINI_HEADLINE_MODEL` to choose it yourself. Full answers, chat and summaries still use `GEMINI_MODEL`, and the first line gets the same prompt and context as before.
  - Thinking-level quirks are now remembered per model, so the first-line model refusing a level never changes the full answers' requests.
  - Diagnostics > Models shows the first-line model.

- **Interview session state (Phase 2a).** Echo now keeps track of the interview itself, in memory only (never saved; cleared on Stop, Clear transcript and quit), in a new pure module `src/main/interview-session.js`.
  - **Question threads**: every interviewer question is linked as a **new** topic or a **follow-up** of an earlier one, with a confidence and the reasons. Explicit transitions ("let's move on", "next question") start a new thread; "why a hash map?", "what's the space complexity?", "what was the outcome?", "what would you do differently?" stay with their thread; "going back to your two-sum solution" / "earlier you mentioned the payments project" find the older thread. An unclear one ("walk me through that" right after a topic change) is kept **provisional** with both readings and settled by what comes next (usually your own answer).
  - **Sources kept apart**: every stored item says who said it (interviewer, you, an Echo suggestion, your knowledge files, or a rule) and its status (stated, suggested, confirmed, inferred, superseded). Constraints, interviewer facts and your experience claims are labels on the verbatim lines.
  - **Only what you actually said counts**: a detail from Echo's suggestion ("hash map", "O(n)", a tool, a number, a project name from your CV) becomes confirmed only when you say that specific thing yourself in the same thread. Keyword overlap never confirms a whole suggestion.
  - **Better CV lookup for follow-ups** (the only change answers see): "What did you learn from it?" now searches your knowledge files with the original question and the names you mentioned in your answer, and prefers the snippets already used for that story, instead of searching for the word "learn". New questions are searched exactly as before, and the prompts are unchanged.
  - Diagnostics (`Ctrl+Shift+D`) shows the thread of the last answer, e.g. `#3 follow-up (0.82)`.

- **Meeting intelligence: intent detection and mode-specific answers.**
  - New rule-based intent layer (`src/renderer/intent-core.js`, no extra API calls): each `Them` line is labelled as a direct question, opinion request, follow-up, disagreement, proposal, request for ideas, clarification, explanation request, behavioural or technical question, a problem / blocker, information sharing, or nothing to answer (fillers, "sounds good", "thanks").
  - **Automatic answers** in Meeting and General mode now also fire on things that need a reply but aren't phrased as questions: "I don't think that'll work" (when it's a reply to you), "What if we cached it?", "We're blocked on the API keys", "Any ideas?". Updates and small talk don't fire. **Interview mode triggers exactly as before.** `You` lines never trigger; Privacy Mode still pauses automatic answers.
  - **Mode-specific prompts**: one shared core (truth first, voice rules and tone examples, answer style) plus one block per mode. STAR and the coding walk-through are now Interview-only. Meeting answers take a clear position, handle pushback without getting defensive or caving, respond to proposals with a benefit / risk / improvement, and may lead with a question. Presentation gives talking points and a way back to the main point. General replies naturally. The detected intent goes in the request (not the system prompt), so prompt caching still works.
  - **"Nothing to add"**: outside interviews, an automatic answer can come back as nothing; Echo then shows nothing at all (Diagnostics > Last auto trigger says so). Answers you ask for always answer.
  - The instant first line and the full answer now share one analysis of the question (kind + intent). Unknown modes from the UI are treated as General.
  - New voice rules: no reflexive agreement or praise ("Great point", "I completely agree"), and no opening with the other person's name or "So basically".

- **Adjustable see-through background.** Settings > **Appearance** > **Transparency**: a slider from 0% (solid, the old look) to 85%, with **Solid** / **Light** / **Glass** presets (0 / 30 / 60%). Default is **Light (30%)**, so you can see your call or code editor behind Echo out of the box while body text keeps about 7:1 contrast even over a white page, before the halo. Applies live while you drag (Settings previews the level while you hold the slider) and is remembered (`echo.transparency`). `Ctrl+Shift+T` (new global shortcut) switches between Solid and your level.
  - Only backgrounds fade, never text (no `BrowserWindow.setOpacity`): one CSS variable, `--see-through`, drives the alpha of the frame, answer card, drawers, menu, toast and the Settings / Summary / Diagnostics panels. The answer card always stays darker than the frame; drawers, menus and toasts are capped at 12% / 10% and full-window panels at 20% (with the main view hidden under them) so nothing reads through onto other text.
  - Legibility protection scales with the level: a soft dark text halo, icon drop-shadows, lighter grey labels, slightly bolder answer text, and a dark backing behind the frame's icon buttons, status badges and banner. Checked over a white text page, a bright "video call" and a code editor.
  - Compact bar and Focus mode use the same level. Click-through (`Ctrl+Shift+X`) now dims less when see-through is on (0.55 when solid, up to 0.89 at 85%), so the text stays readable. `prefers-reduced-transparency` keeps Echo solid.

- **Suggestion-first UI.** The answer is what people look at, so the window is now a slim top bar, one large answer card and an icon dock. No behaviour, shortcut or prompt changed.
  - **Top bar**: status dot, one **Start / Stop** button (red with a soft pulse while listening), the mode dropdown, the `⋯` menu, compact bar and hide. Status shows as small icons only while it's on (thinking, Privacy Mode, hidden from screen share, gestures); the Live pill is gone (the green dot and red Stop say it).
  - **Answer card**: bigger first line and body text, a **Script | Cues** toggle and **Generate** in its header, the **New answer ready** chip beside them, and an icon toolbar (Shorten, Expand, Regenerate, **Copy**) as its footer. The empty state is an icon and one line.
  - **Dock + drawers**: Live transcript, Ask the assistant, Knowledge base and Screen context moved out of the main column into drawers that slide up over the lower part of the window, one at a time (`Esc` closes). Dock icons carry counts: new transcript lines, knowledge files, attached screenshots. **Summarize** and one-tap **screenshot capture** are dock buttons. The Mic / System audio dots are in the transcript drawer's header.
  - **Moved**: Focus mode is now in the `⋯` menu (still `Ctrl+Shift+E`) and hides the dock; the second hide button became **Hide Echo** in the menu; Refresh sources and Clear screenshots are icons in the Screen context drawer; Reload is an icon in the Knowledge base drawer.
  - **Settings** is grouped under headings (Speech-to-text & API keys, Answers, Hand gestures, Where your data goes) with one switch style for every on/off option. `Esc` now also closes Summary and Diagnostics.
  - Icons are Echo's own inline SVGs (no icon font, nothing remote); every icon-only button has a tooltip and an accessible name.

- **Faster answers.**
  - **Instant first line** (Settings > Answers, on by default): every answer request also runs a tiny parallel Gemini call (minimal thinking, ~80 output tokens, last ~8k characters of transcript + the last two answers + knowledge snippets) that writes only the first sentence to say, in the same voice rules. It's shown in the big first-line slot as soon as it arrives; when the full answer's own first sentence is ready it replaces that line in place and the body appears below (nothing below it moves). The full answer stays the source of truth for Copy / Shorten / Expand / history. Both calls share cancellation; a first line that fails, or arrives after the full answer started, is dropped silently. Turn it off to save quota (one extra small request per answer).
  - **Smarter thinking level**: Auto now tells a **new problem** ("write a function", "given an array", "design a ...", maths / probability / puzzles, long problem statements, problem screenshots → `high` in Interview mode) from a **follow-up** about code already discussed ("why did you use X", "what if...", "what's the complexity", "how would you test it", edge cases, short conceptual questions → `low`). Follow-ups get a short spoken answer (first line + 1-3 lines, at most a tiny snippet of the changed code) instead of the full numbered walk-through and code. This was the main cause of 3-4 s waits on coding follow-ups.
  - **Earlier start**: "Them" lines count as questions by their wording, not only a `?` (`src/renderer/question-core.js`). With Deepgram, a question fires as soon as `speech_final` arrives (UtteranceEnd stays the fallback); with Groq, 150 ms after a question chunk lands (was 300 ms / 1.5 s without punctuation), and the VAD now cuts after 550 ms of quiet (was 700 ms). Lines that trail off ("and the...") still wait.
  - The **New answer ready** chip appears as soon as a background answer has its first line; clicking it while the answer is still streaming hands the panel to it.
  - **Prompt layout**: the LATEST question now comes after the screenshots (images are their own parts between the context and the question). The long, append-only transcript stays first so Gemini's implicit prefix caching can reuse it between questions; per-question parts (knowledge snippets, the newest answer, the format hint) come after it.
  - Output budgets: follow-ups get 700 visible tokens; thinking headroom is now 1536 (low) / 3072 (medium) / 8192 (high) tokens on top of the visible budget.
  - Diagnostics: the latency stat counts the first word from either call, and a new row splits the last answer into end of speech → request, request → first line, request → full answer.

- **Deepgram Nova-3 live speech-to-text (optional).** Settings > **Speech-to-text**: Groq Whisper (free, default) or Deepgram Nova-3 (live, faster). With Deepgram, words appear in the transcript as people speak (a dimmed in-progress line per speaker), and Deepgram's end-of-speech signals (`speech_final` / `UtteranceEnd`) trigger automatic answers. Needs an optional third key (Deepgram: $200 free credit, no card; about $0.46/hour of streamed audio after that).
- The WebSocket lives in the main process (`src/main/deepgram.js`, using the `ws` package), so the Deepgram key never reaches the UI. Audio is captured with an AudioWorklet (ScriptProcessorNode fallback), converted to 16 kHz 16-bit PCM and streamed only while someone is talking. KeepAlive while idle, CloseStream on stop, up to 3 reconnects, then an automatic fall back to Groq Whisper when a Groq key is set.
- Start Listening now needs Gemini + the chosen speech-to-text provider's key; the banner and Settings say which one is missing. **Test keys** also checks the Deepgram key (a free, read-only request).
- `setup.cmd` / `setup.ps1`: one-click Windows setup for people running from source. Checks Git and Node.js (offers to install Node LTS with winget), puts local `package.json` / `package-lock.json` changes aside so `git pull` works, runs `npm install` with retries, then builds and launches the installer or runs `npm start`.
- Node.js **22.12 or newer** is now required to build (`engines` in `package.json`); Electron's npm package and electron-builder's dependencies need it.
- **Upgraded Electron 31 → 45** (45.3.2: Chromium 156, Node 24.22). Electron 31 is out of support and had open security advisories.
  - System audio: Electron 45 reports `getUserMedia` desktop capture as a `display-capture` permission instead of `media`, which the old handler denied, so system audio would have silently stopped working. Main now grants `display-capture` to Echo's own page only for a few seconds after `desktop:get-audio-source`, and `media` video (the camera) only while hand gestures are on (it no longer needs the desktop-capture window).
  - Keys: `keyStore.js` uses `safeStorage`'s async API (the sync one is deprecated in 45 and removed in 46). Keys saved by earlier versions still decrypt; the saved keys are decrypted once at startup.
  - `clipboard.writeText` in main is awaited (a Promise since Electron 44); the renderer `console-message` forwarder uses the event-object form only.
  - The Electron runtime is no longer downloaded by `npm install` (Electron 42+): the first `npm start` downloads it, `npm run dist` / `npm run pack` download it first, and `npm run electron:fetch` does it by hand. `setup.cmd` fetches it right after `npm install`, with retries.

## 0.1.0

First open-source, bring-your-own-keys release.

- Always-on-top overlay that transcribes your mic ("You") and system audio ("Them") in ~6 s chunks with Groq Whisper.
- Automatic answer suggestions when the other side asks a question, plus Generate (`Ctrl+Enter`), Shorten, Expand, Regenerate and Copy.
- Streaming answers from Google Gemini; automatic answers wait behind a "New answer ready" chip instead of replacing the one you're reading.
- Interview, Meeting, Presentation and General modes; Quality vs speed setting (Auto / Fast / Max).
- Screenshot tray (up to 4), knowledge base from your own `.txt` / `.md` files, chat box, and session summaries with export.
- Compact bar, Focus mode, Privacy Mode, hide from screen share (opt-in), click-through, diagnostics panel and global shortcuts.
- Experimental webcam hand gestures (off by default, processed locally with MediaPipe).
- API keys encrypted with the OS keychain via Electron `safeStorage`; no Echo server, no login, no credits.
- Windows installer (`Echo-Setup-<version>.exe`, NSIS x64) built with electron-builder via `npm run dist`; not code-signed yet.
- GitHub Actions: CI runs a syntax check and `npm test` on Windows and Ubuntu; pushing a `v*` tag builds the installer and attaches it to a GitHub Release.
